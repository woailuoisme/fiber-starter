# 2. 特性间交叉调用采用直接具象 Service 调用与单向依赖约束

为了实现极简开发、减少封装层次与文件冗余，我们决定特性（Feature）之间允许直接通过 `import` 导入并调用对方的具象 Service 实现，无需编写接口（Interface）桥接与冗余 DTO。

为规避 Go 的循环导入错误，特性间的调用关系必须严格约束为**单向依赖流**（例如，高层业务 `order` -> 底层基础 `user` -> `notification`）。如果底层基础特性在偶发场景下需要依赖特性（如 `order`）的数据，基础特性严禁导入依赖特性的包，必须直接通过全局 DB 连接（Bun DB）跨表查询所需的原始数据，从而阻断编译期双向依赖链。
